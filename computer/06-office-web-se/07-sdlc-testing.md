## 1. Definitions

> **Software engineering:** systematic, disciplined approach to design, develop, operate, and maintain software.  
> **SDLC (Software Development Life Cycle):** the sequence of stages from idea to retirement of software.

---

## 2. SDLC stages (classic waterfall list)

| Stage | Work | School analogy |
|-------|------|----------------|
| **1. Requirement** | What the user needs | HM wants a marks software |
| **2. Feasibility** | Can we? cost/time | Budget, computers |
| **3. Design** | How it will look/work | Registers, screens |
| **4. Implementation / coding** | Write programs | Type Python/C |
| **5. Testing** | Find defects | Try wrong marks, 0, 100 |
| **6. Deployment** | Install for users | Put on school PC |
| **7. Maintenance** | Fix and update | New exam pattern |

---

## 3. Models (one line each)

| Model | Idea | Merit / demerit |
|-------|------|-----------------|
| **Waterfall** | One way down; no going back easily | Simple docs; bad if needs change |
| **Iterative / Incremental** | Build in pieces | Feedback |
| **Spiral** | Risk analysis loops (Boehm) | Good for large risky projects |
| **Prototype** | Dummy first | Users see early |
| **Agile** | Short sprints, daily stand-up | Flexible; needs close user |
| **V-model** | Testing planned against each stage | Quality focus |

---

## 4. Testing basics

> **Testing:** executing software to find errors and check it meets requirements.

| Type | Meaning |
|------|---------|
| **Unit** | One function / module |
| **Integration** | Modules together |
| **System** | Whole software |
| **Acceptance / UAT** | User says OK |
| **Regression** | Old features still work after a change |
| **Alpha** | Inside company |
| **Beta** | Outside users |
| **Black box** | No look at code; only input/output |
| **White box** | Look at code paths |
| **Smoke** | Basic “does it start?” |

**Verification:** are we building the product **right**? (reviews)  
**Validation:** are we building the **right** product? (user needs)

**Bug / defect / error / failure** — error in human thought → defect in code → failure when run.
